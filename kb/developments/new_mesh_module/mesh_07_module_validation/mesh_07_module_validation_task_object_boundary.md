# FEALPy | Task Object Boundary | 新网格模块团队研究工作验证 任务对象边界

- **版本**：v0.1
- **状态**：草案
- **入库位置**：`kb/developments/new_mesh_module/mesh_07_module_validation/mesh_07_module_validation_task_object_boundary.md`
- **启用条件**：当需要明确当前 Task 直接建设什么、不直接建设什么、与相邻对象如何分界，以及边界变化如何回流时，本文件必须启用
- **适用范围**：新网格模块合并 `develop` 后的团队研究工作验证、缺陷收集与结果回流

本文档定义 `mesh_07_module_validation` 的对象边界，防止把研究工作验证扩张为研究项目改造、集中 Bug 修复或最终验收。

## 一、上游依据与边界定位

| 上游资产或输入 | 对当前边界的支撑内容 | 依据状态 | 使用边界 |
|---|---|---|---|
| `mesh_07_module_validation_task_requirement.md` | 确定逐成员真实场景验证、缺陷可追溯与修复分离要求 | Fact | 当前 Task 直接依据 |
| `mesh_07_module_validation_task_brief.md` | 确定本任务为 07 节点以及 O-01~O-04 输出预期 | Fact | 不重写 Brief |
| 父任务网络 | 07 可回流 05/06，并向 08 提供输入 | Fact | 不承担 05/06/08 的主位责任 |

## 二、直接建设对象

| 对象编号 | 直接建设对象 | 建设职责 | 成立依据 | 使用边界 |
|---|---|---|---|---|
| B-IN-01 | 本轮验证基线与成员适用性登记 | 记录统一 commit、环境要求、成员是否有 FEALPy 研究工作及代表性用例 | R-01~R-03 | 不改变成员研究目标 |
| B-IN-02 | 成员验证记录 | 记录真实研究流程的输入、命令、预期依据、实际结果、状态和限制 | O-01 | 可脱敏，不接收无依据的通过结论 |
| B-IN-03 | 缺陷候选与复现材料 | 收集异常并形成可复核的最小复现或阻塞说明 | O-02 | 不预先裁定根因 |
| B-IN-04 | 缺陷台账 | 去重、分类、分级、标记复核状态和建议承接对象 | O-03 | 不替代正式 Issue 系统和修复计划 |
| B-IN-05 | 验证结果摘要 | 汇总覆盖、结果、风险、限制和 mesh_08 接口 | O-04 | 不形成最终验收结论 |

## 三、不直接建设对象

| 对象编号 | 不直接建设对象 | 排除原因 | 与当前 Task 的关系 | 承接接口 |
|---|---|---|---|---|
| B-OUT-01 | 团队成员研究方法、论文结论或完整研究代码 | 仅作为真实验证场景，不是本任务建设目标 | 提供用例和预期依据 | 各研究工作负责人 |
| B-OUT-02 | 新网格模块大规模 Bug 修复 | 本任务主位是发现、复现、分类和回流 | 可形成修复建议与回归测试候选 | mesh_05、专项修复 Task 或责任维护者 |
| B-OUT-03 | 测试覆盖率体系完善 | 已由 mesh_06 承担 | 缺陷可触发补测需求 | mesh_06 |
| B-OUT-04 | `develop` 合并操作、发布和版本冻结 | 属于仓库治理与发布责任 | 合并是本任务进入条件 | 仓库负责人 |
| B-OUT-05 | 新网格模块最终验收 | 需要总负责人和网格组联合判断 | 本任务只提供 V&V 输入 | mesh_08 |
| B-OUT-06 | 无 FEALPy 研究成员的人造演示算例 | 不能代表其真实研究用途 | 以不适用声明替代 | 后续专项示例任务（如需要） |

## 四、使用、引用或依赖对象

| 对象编号 | 使用对象 | 使用方式 | 来源 | 不构成直接建设的边界 |
|---|---|---|---|---|
| B-USE-01 | 合并后的 `develop` | 作为统一运行基线 | FEALPy 仓库 | 不由本任务执行合并或冻结发布 |
| B-USE-02 | 成员研究工作及数据 | 运行真实上层流程并给出预期依据 | 团队成员 | 不要求整体迁入 FEALPy 仓库 |
| B-USE-03 | 既有新网格测试和设计文档 | 定位、对照和辅助复现 | `tests/mesh/`、`kb/developments/new_mesh_module/` | 不重复建设完整测试体系 |
| B-USE-04 | 旧实现或合并前结果 | 在可用时作为比较参考 | 既有分支、记录或发布版本 | 参考结果不自动成为正确性证据 |

## 五、相邻对象分界

| 相邻对象 | 当前 Task 的职责 | 相邻对象的职责 | 分界依据 | 边界状态 |
|---|---|---|---|---|
| mesh_05 算法迁移 | 发现并记录迁移遗漏、提供复现和影响 | 修复算法迁移问题并反馈结果 | 父任务 07 -> 05 回流 | 已定义，具体负责人待定 |
| mesh_06 测试覆盖 | 提供 Bug 最小用例和补测需求 | 将确认缺陷固化为回归测试并补强覆盖 | 父任务 07 -> 06 回流 | 已定义，具体入口待定 |
| 团队研究工作 | 只验证 FEALPy 相关调用并记录影响 | 研究负责人说明用途、预期与可公开边界 | R-02、C-03 | 按成员登记 |
| 正式 Issue / 修复任务 | 提供候选问题和证据输入 | 完成根因确认、责任分派、修复与关闭 | R-06、R-07 | 跟踪入口待裁决 |
| mesh_08 最终验收 | 提供经复核摘要、缺陷和剩余风险 | 形成最终验收和后续治理结论 | 父任务网络 | 清楚 |

## 六、边界变化与回流接口

| 边界变化情形 | 需要回流检查的上游资产 | 需要联动判断的下游资产或对象 | 当前处理状态 |
|---|---|---|---|
| `develop` 基线在验证窗口内变化 | Requirement / Brief | 全部成员记录是否重跑 | 待负责人制定冻结规则 |
| 缺陷表明新网格 API 设计不满足真实用途 | Requirement / Boundary | mesh_03/05、设计资产、专项修复 | 按影响范围回流 |
| 缺陷已有重复或被证明是上层误用 | 无 | 缺陷台账、成员记录、文档接口 | 保留原始记录并更新状态 |
| 发现重大阻塞或数据错误风险 | Requirement / Brief | 模块负责人、mesh_08 进入条件 | 立即升级人工复核 |
| 研究材料无法公开 | Boundary | Supporting Material 与复核方式 | 采用脱敏输入或受控复核 |

## 七、待核验与待裁决事项

### 7.1 待核验事项

| 事项 | 核验原因 | 所需输入或证据 | 影响范围 |
|---|---|---|---|
| 各研究场景允许入库的材料范围 | 可能受数据、代码和论文阶段约束 | 成员声明 | 复现与第三方使用 |
| 是否需要跨后端、跨平台复测 | 应由实际失败和项目支持范围触发 | 首轮记录、CI 支持矩阵 | V&V 范围 |

### 7.2 待裁决事项

| 事项 | 需要裁决的内容 | 裁决责任主体 | 影响范围 |
|---|---|---|---|
| 重大缺陷的停止线 | 哪些问题应暂停后续验收或要求全员复测 | 模块负责人、项目负责人 | mesh_08 进入条件 |
| 修复是否纳入本 Task | 默认不纳入；需决定紧急修复的例外流程 | 项目负责人 | 代码边界和基线稳定性 |
