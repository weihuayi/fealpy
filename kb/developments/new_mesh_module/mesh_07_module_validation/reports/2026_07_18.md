
基于 fvm_validation_record.md 的两个失败用例，以及当前 Mesh 架构中 `EntitySchema -> MeshBlock/EntitySector
-> EntityView` 的职责设计，当前代码层面的待修改清单如下。此次未修改代码。

一、必须修复的问题

1. 修复四边形面的节点顺序与几何算法之间的不一致
    - 涉及文件：fealpy/mesh/schema/classic/quadrilateral.py
    - 重点位置：QuadrilateralSchema.normal()、measure()、tangent()、jacobi_matrix() 及相关几何函数。
    - 当前问题：
        - TopologyBuilder 生成的 quad sector 保留的是 OFace 的环状节点顺序。
        - QuadrilateralSchema 内部又统一使用 quad[:, [0, 1, 3, 2]] 重排。
        - 对六面体生成的四边形面，这种重排可能把原本连续的环状节点变成交叉顺序，导致叉积相互抵消。
        - 结果是四边形面的 measure() 仍可能正确，但 normal() 返回零向量。
    - 待修改方向：
        - 明确 quad sector 的统一节点顺序契约。
        - 要么让所有四边形几何算法直接遵守 sector 的实际环状顺序；
        - 要么在拓扑构造阶段统一转换为 QuadrilateralSchema 所需的张量积顺序。
        - 不应在不同算法中隐式假定两套节点顺序。

> [!NOTE]
> 这暴露出一个问题——QuadrilateralSchema 的节点顺序假设与它在高维实体 OFace 里的顺序不一致。
> 必须明确，我们以 OFace 中为准，保证四边形中顶点按逆时针顺序排列。
> 决策：修改 QuadrilateralSchema 的几何算法，遵守 OFace 的环状顺序，而不是在 schema 内部使用张量积顺序。

2. 修复三维四边形面的法向计算
    - 涉及文件：fealpy/mesh/schema/classic/quadrilateral.py
    - 重点位置：QuadrilateralSchema.normal()。
    - 当前问题：
        - 六面体单位立方体的六个 quad face 的 EntityView.normal() 全为零。
        - 三维四边形面的法向应由两个非退化切向量叉积得到，至少应保证非零几何法向。
    - 待修改方向：
        - 使用经过确认的边界环顺序计算面法向；
        - 对平面四边形，保证返回稳定的面积法向；
        - 对非平面四边形，明确采用三角剖分法向、平均法向或其它统一约定；
        - 与 measure() 的节点顺序和方向约定保持一致。

> [!NOTE]
> 同上，约定四边形中的顶点按逆时针顺序排列。
> 另外，还需要同步修改一下 mesher/box.py 中的四边形生成。
> 决策：同上。

3. 修复 FEALPyMesh.face_normal() 的返回形状假设
    - 涉及文件：fealpy/mesh/view/fealpy_api.py
    - 重点位置：约第 638–649 行的 face_normal()。
    - 当前问题：
        - block.normal() 当前对四边形返回二维数组 (NF, GD)；
        - face_normal() 却固定执行 block.normal(...)[:, 0, :]，假定返回 (NF, 1, GD)；
        - 因此稳定触发：
        IndexError: too many indices for array: array is 2-dimensional, but 3 were indexed
    - 待修改方向：
        - 统一 EntitySchema.normal() 的标准输出契约，或在 Mesh 兼容层集中适配不同实体形状；
        - face_normal() 必须对 quad、tri 以及可能的混合面类型返回一致的 (NF, GD)；
        - 不应依赖具体 schema 的内部维度实现。

> [!NOTE]
> Schema 和 EntityView 中一定返回三维数组，含义是 (NE, NN, GD)，其中 NE 是实体数，NN 是每个实体的法向数，GD 是几何维数（对于二维实体，NN 恰好为 1）；
> 而 face_normal 属于兼容接口，一定返回旧的二维数组 (NE, GD)。
> 决策：确保 block.normal() 返回 (NE, NN, GD)，而 face_normal() 返回 (NE, GD)。

4. 修复 FEALPyMesh.face_unit_normal() 的同类维度问题
    - 涉及文件：fealpy/mesh/view/fealpy_api.py
    - 重点位置：约第 651–664 行。
    - 当前问题：
        - 与 face_normal() 使用相同的 [:, 0, :] 错误假设；
        - 即使法向计算修复，当前接口仍可能因返回维度不一致而失败。
    - 待修改方向：
        - 复用修正后的 face_normal() 或统一后的法向接口；
        - 对零法向增加明确处理，避免静默产生 NaN/Inf；
        - 返回结果应满足 (NF, GD)，每个有效面向量范数为 1。

> [!NOTE]
> 决策：同意。

5. 修复通用实体积分缺少逐积分点 Jacobian 测度因子的问题
    - 涉及文件：fealpy/mesh/schema/classic/base.py
    - 重点位置：约第 123–134 行的 ShapedEntitySchema.integral()。
    - 当前问题：
        - 当前实现为：
        measure * reference_weight * value
        - 该公式只有在 Jacobian 测度因子为常量时才成立。
        - 对一般双线性四边形，Jacobian 随参考积分点变化，导致：
        - integral(x) 返回 1.125，正确值为 7/6；
        - integral(y) 返回 0.75，正确值为 2/3。
    - 待修改方向：
        - 在每个积分点计算参考到物理映射的 Jacobian；
        - 根据实体类型和嵌入维度计算正确的测度因子：
        - 体单元：abs(det(J))；
        - 曲面实体：由 Gram 矩阵确定面积因子；
        - 线实体：由切向 Jacobian 确定长度因子；
        - 采用逐实体、逐积分点的权重进行积分，而不是使用单个常数 measure 替代。

> [!NOTE]
> 属于数学层面的问题，修改前，应明确数学过程和理论依据。
> 决策：明确数学过程后修改即可，注意使用 einsum 或类似方法避免循环。

6. 明确 integral() 与 jacobi_matrix() 的统一数据契约
    - 涉及文件：
        - fealpy/mesh/schema/entity_schema.py
        - fealpy/mesh/schema/classic/base.py
        - 各 concrete schema 的 jacobi_matrix() 实现。
    - 当前问题：
        - EntityView.jacobi_matrix() 文档声明通常返回 (NE, NQ, GD, ref_dim)；
        - integral() 没有利用该接口提供的逐点 Jacobian 信息；
        - 这使得公共积分接口和几何映射接口对非仿射单元的语义不一致。
    - 待修改方向：
        - 明确 jacobi_matrix() 对所有实体类型的轴顺序、参考维数和嵌入维数；
        - 明确如何从 Jacobian 计算统一的积分测度因子；
        - 让 integral() 基于该统一契约实现，而不是由各上层模块自行拼装。

> [!NOTE]
> 这与上一点相关
> 决策：同意你的判断。

        - 确保映射、形函数、测度、法向和切向彼此一致。

8. 复核六面体生成 quad face 的 OFace / SFace 语义
    - 涉及文件：
        - fealpy/mesh/schema/classic/hexahedron.py
        - fealpy/mesh/schema/classic/quadrilateral.py
        - fealpy/mesh/topology/builder.py

    - 不能仅通过在 normal() 中增加一个固定排列来掩盖拓扑编号契约不清的问题。

9. 复核棱柱和棱锥中的四边形面
    - 涉及文件：

    - 原因：

        - 应确认修复不会只对六面体成立。

10. 复核六面体体积分是否存在同类 Jacobian 权重错误
    - 涉及文件：fealpy/mesh/schema/classic/hexahedron.py
    - 原因：
        - 当前 ShapedEntitySchema.integral() 是公共实现；
        - 非仿射六面体也使用随参考坐标变化的 trilinear Jacobian；
        - 不能只修复 quadrilateral 后假设三维体单元自动正确。
    - 需要验证：
        - 规则六面体；
        - 非仿射六面体；
        - 常数函数；
        - 一次坐标函数；
        - 必要时二次函数。

11. 复核三角形、四面体和规则四边形路径，避免引入回归
    - 验证记录未判定这些路径失败，但积分实现属于公共基类；

        - 三角形积分仍保持正确；
        - 四面体积分仍保持正确；
        - 仿射四边形积分数值不变；
        - 常数函数积分仍等于 measure()。

三、接口契约与兼容层问题

12. 统一 EntitySchema.normal() 的标准返回形状
    - 涉及文件：
        - fealpy/mesh/schema/entity_schema.py
        - fealpy/mesh/view/entity_view.py
        - 各实体 schema。
    - 当前状态：
        - EntityView.normal() 文档写的是常见形状 (NE, NN, GD)；
        - QuadrilateralSchema.normal() 实际返回 (NE, GD)；
        - FEALPyMesh.face_normal() 又假定 (NE, 1, GD)。
    - 待修改方向：
        - 明确标准函数的唯一返回形状；
        - 所有 schema 遵守同一契约；
        - 视图层和兼容层不得分别猜测实体实现的维度。

13. 明确法向方向的职责边界
    - Mesh 层应负责：
        - 根据实体几何和局部节点顺序计算一致法向；
        - 保证非零、有限、形状稳定。
    - FVM 层应负责：
        - 根据 owner-neighbour 关系选择或统一法向正负；
        - 构造面面积向量及通量方向。
    - 不应把全局 owner-neighbour 朝向逻辑混入基础几何法向修复，也不应要求 FVM 重复计算面几何。

14. 避免 face_unit_normal() 对退化面静默除零
    - 当前 normal / norm 没有退化检查。
    - 待明确：
        - 退化实体是否抛出异常；
        - 是否返回标记；
        - 是否允许 NaN；
        - 该行为应与 measure() 的退化实体处理保持一致。
    - 对正常非退化实体，必须增加回归断言：单位范数、有限值、正确输出形状。

五、暂不应列为本轮 Mesh bug 的事项

- barycenter() 当前返回顶点平均值的问题，验证记录已明确保留其语义解释空间，不应在本轮直接作为缺陷修改。
- 不能据此下结论称“新 Mesh 整体不兼容 FVM”。
- 三角形、规则二维四边形和四面体路径目前没有被该记录判定为失败，应通过回归测试确认，而不是预先大范围重写。
- 不建议让 FVM 长期自行从局部节点和 Jacobian 重算面法向或积分权重；这会违反 Mesh 几何职责边界并复制通用算法。
