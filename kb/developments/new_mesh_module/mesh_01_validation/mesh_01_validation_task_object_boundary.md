# FEALPy | Task Object Boundary | 新网格模块稳定化验证 对象边界

- **版本**：v0.1
- **状态**：草案
- **入库位置**：`kb/developments/new_mesh_module/mesh_01_validation/mesh_01_validation_task_object_boundary.md`
- **启用条件**：当需要界定当前 Task 的对象边界时，本文件必须启用
- **适用范围**：`fealpy.mesh` 新网格模块学习、审查、算例与新类型验证范围

本文档用于界定当前 Task 直接建设什么、不直接建设什么，以及与相邻对象如何分界。

## 一、边界定位

本任务只处理 `fealpy.mesh` 新网格模块的学习、审查、算例落地、新网格类型实现与验证设计，不替代全仓库重构，也不替代其他模块的独立演进。

## 二、纳入范围

本任务范围内必须覆盖以下对象：

- `fealpy/mesh/schema`：实体规则模板与注册表
- `fealpy/mesh/storage`：网格事实存储与关系承载
- `fealpy/mesh/topology`：拓扑构造、边界推断、局部关系推断
- `fealpy/mesh/view`：用户访问入口与实体视图
- `kb/design/mesh` 与 `kb/implementation/mesh`：现有架构说明、构造链路说明、边界推断说明
- 算例、测试、验证脚本与必要的辅助文档

本任务内必须完成的工作：

- 阅读文档与代码，理解新网格模块分层。
- 指出当前架构中职责混淆、接口脆弱、缓存一致性、命名不统一或拓扑假设过强之处。
- 以各自研究主线为牵引，完成一个只依赖新网格模块的完整算例。
- 在需要时补充网格相关算法或 mesher，但补充范围应服务于算例完成，不要求覆盖全部场景。
- 以新架构实现一种新的网格类型，并给出正确性验证方案。
- 为后续协作准备可复用的验证与测试资产。

## 三、排除范围

以下内容不在本任务主范围内：

- 全仓库旧网格模块的全面迁移或一次性替换
- 与网格无直接关系的求解器重构
- 大规模性能优化与并行化改造
- 所有现有算例的全面适配
- 对所有 mesher 能力的全覆盖实现
- 仅写结论、不落地代码或测试的纯讨论

## 四、相邻对象分界

- 架构审查只围绕新网格模块本体，不把旧接口惯性当作正确性依据。
- 算例只允许以新网格模块作为主入口，不允许用旧网格模块绕过新架构。
- 新网格类型实现必须明确它是新的实体规则、存储结构还是视图扩展，不能混写成“顺手加一个类”。
- 验证方案必须可执行，不能只给原则性结论。
- 建议审查重点包括：
	- `schema / storage / view` 的职责是否真正分离
	- `MeshBlock`、`EntitySector`、`Relation` 的最小职责是否足够清晰
	- `TopologyBuilder` 与 `TopologyInferer` 的算法边界是否清楚
	- 边界信息推断、关系推断、局部索引推断是否存在隐式前提
	- `EntityView` 是否过度依赖 schema 内部实现
	- 新网格类型注册、构造、查询、验证是否有一致的工程入口

## 五、待确认边界点

- 暂无新增待确认边界点。
