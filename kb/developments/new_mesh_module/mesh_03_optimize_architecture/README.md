## 🎯 使用路径建议

### 场景 1：项目经理 / 团队负责人
1. 阅读 **Brief** → 理解任务目标
2. 阅读 **Requirement** → 确认需求的完整性
3. 阅读 **Network Design** → 理解任务拆分与依赖
4. 阅读 **Execution Workflow** → 制定执行计划与分工
5. 参考 **Target Asset Design** → 规划资产输出

### 场景 2：AI Agent / 开发者
1. 阅读 **Brief** → 理解任务意义
2. 阅读 **Requirement** → 明确需要实现的 8 项优化
3. 阅读 **Network Design** → 了解每一步的具体操作
4. 按 **Execution Workflow** 逐步执行（S1 → S2 → ... → S9）
5. 在每步完成后接受人工检查点验收（CP1 ~ CP8）

### 场景 3：人工验收者 / 质量负责人
1. 阅读 **Brief** → 了解优化目标
2. 参考 **Execution Workflow** 中的验收清单
3. 在 8 个检查点时快速验收（CP1~CP8，每个 15~40 分钟）
4. 最后在 W6 进行集成验收（CP8）

### 场景 4：后续使用者（如 mesh_04_算例改写）
1. 阅读 **Brief** → 了解优化的目标
2. 阅读 **Target Asset Design** → 查找迁移指南等资源
3. 参考 **Requirement** → 了解新 API 的形式
4. 查找改写后的算例代码展示新 API 使用

## ❓ 常见问题

**Q: 这个任务需要多久完成？**  
A: 预计 6 周（W1~W6），假设团队有 2~3 名核心开发者。关键路径：需求确认 → 缓存失效 → 反向邻接 → 便利 API → 文档。

**Q: 我应该从哪个 Node 开始？**  
A: 根据你的职能选择：
- 开发者：从 Node 2.1~2.4 中选一项并行优化
- 测试：从 Node 1.2 开始搭建测试框架
- PM：从 Network Design 开始评估依赖与并行度

**Q: 向后兼容性如何保证？**  
A: 通过 Node 3.1（回归验证）与 Node 3.2（集成验证）。mesh_01_validation 中的 Line Walk 与四面体质量算例应继续可运行。

**Q: 文档什么时候更新？**  
A: 集中在 W5~W6 的 Node 4.1，但代码改动时应同步更新代码注释。
