## 一、Validation 设计定位

本任务验证不只检查"代码能跑"，还检查"优化确实改进了可用性、没有破坏现有功能、向后兼容性清晰"。验证主位是证明 8 项优化都有效实现、接口设计合理、测试充分。

## 二、待验证对象与对象级完成判据对应关系

| 优化项 | 待验证对象 | 完成判据 |
|--------|----------|---------|
| **1. 反向邻接查询** | 反向关系推断与邻接 API | 用户能直接查询 `edge → tri`，结果正确 |
| **2. 几何自适应** | 二维/三维几何接口 | 二维/三维网格都能无异常调用 measure / normal |
| **3. opposite-vertex 元数据** | 局部顺序与元数据完整性 | 所有 simplex schema 都有明确的方向约定 |
| **4. 缓存失效** | 缓存一致性 | 拓扑修改后重查边界，结果与变化同步 |
| **5. 接口管理** | EntitySchema 能力声明与错误提示 | 调用未实现接口给出有意义错误信息 |
| **6. 术语统一** | 文档与代码术语对齐 | 跳转文档与代码，术语能对得上 |
| **7. 双重实体查询** | 形状+维数组合查询 | 用户能快速按形状+维数查询实体 |
| **8. 便利 API** | view 层常用接口 | 常见邻接、边界、梯度查询一行代码完成 |

- 子任务 V1：元数据与接口文档化验证
- 子任务 V2：几何接口维数自适应验证
- 子任务 V3：缓存失效机制验证
- 子任务 V4：接口管理完善验证
- 子任务 V5：反向邻接查询验证
- 子任务 V6：形状+维数查询验证

## 四、单子任务主类型、验证路径与 Workflow 模式

### V1. 元数据与接口文档化验证

- **主类型**：结构与文档一致性验证
- **验证路径**：代码属性 / 文档查看
- **关注点**：
  - `TriangleSchema` 有 `opposite_vertex_edges` 或类似属性
  - `EdgeSchema`、`TetrahedronSchema` 等也有相应元数据
  - 文档中清晰说明各 schema 的方向约定
- **验证方法**：代码审查 + 文档检查

### V2. 几何接口维数自适应验证

- **主类型**：功能正确性验证
- **验证路径**：二维/三维网格的几何计算
- **关注点**：
  - 二维坐标网格的 `measure()` 返回行列式面积
  - 三维坐标网格的 `measure()` 返回标量体积
  - 维数不匹配时有清晰错误提示
  - `normal()` 的二维/三维语义清晰
- **验证方法**：单元测试 + 解析参考对比
- **参考数据**：正方形面积、正四面体体积、规则二维三角形等

### V3. 缓存失效机制验证

- **主类型**：一致性验证
- **验证路径**：修改拓扑 → 重查边界 → 结果检查
- **关注点**：
  - 调用 `add_sector()` 后缓存清空
  - 修改 relation 后缓存清空
  - 重查边界时得到最新结果
  - 无缓存漏洞或重复计算
- **验证方法**：单元测试 + 追踪缓存生命周期

### V4. 接口管理完善验证

- **主类型**：接口清晰性验证
- **验证路径**：调用各 schema 接口
- **关注点**：
  - 已实现接口能正常调用
  - 未实现接口报 `NotImplementedError` 或明确提示
  - 错误信息包含"当前 schema 不支持"或类似提示
  - 接口能力文档清晰
- **验证方法**：代码审查 + 错误信息检查

### V5. 反向邻接查询验证

- **主类型**：功能正确性验证
- **验证路径**：构造网格 → 查询邻接 → 验证正确性
- **关注点**：
  - 能查询 `edge → tri` 邻接
  - 能查询 `tri → tri` 或 `cell_to_cell` 邻接
  - 邻接结果与前向关系一致
  - 边界边邻接数量为 1，内部边为 2
- **验证方法**：单元测试 + 已验证网格对比（mesh_01_validation 网格）

### V6. 形状+维数查询验证

- **主类型**：接口易用性验证
- **验证路径**：按形状+维数组合查询
- **关注点**：
  - `mesh.entity("triangle", 2)` 能工作
  - 维数不匹配的查询有清晰反馈
  - 查询结果正确
- **验证方法**：示例脚本 + 单元测试

### V7. 便利 API 验证

- **主类型**：功能正确性与易用性验证
- **验证路径**：调用便利 API → 结果检查
- **关注点**：
  - `cell_to_cell_neighbors()` 返回正确的邻接关系
  - `on_boundary()` 返回正确的边界实体
  - `gradient_indices()` 返回正确的梯度计算所需索引
  - API 调用简洁，无冗长参数
- **验证方法**：单元测试 + Line Walk / 质量计算算例应用

### V8. 术语与迁移验证

- **主类型**：文档与代码一致性验证
- **验证路径**：从设计文档跳转代码 → 术语核对
- **关注点**：
  - 设计文档更新为代码术语（MeshBlock 而非 MeshStorage）
  - 术语映射表清晰可用
  - 迁移指南能指导用户改写代码
- **验证方法**：人工审查 + 新用户测试

### V9. 回归验证

- **主类型**：兼容性验证
- **验证路径**：运行 mesh_01_validation 中的算例
- **关注点**：
  - Line Walk 算例仍能运行
  - 四面体质量计算算例仍能运行
  - 现有测试套件通过率不降
- **验证方法**：自动化测试 + 手动回放

## 五、Validation 子任务产出资产设计

- 断言型单测：适合验证接口返回值、缓存一致性、邻接关系等离散结果。
- 解析对照材料：验证几何量、维数自适应、向量计算是否符合理论。
- 算例回放材料：用 mesh_01_validation 中的 Line Walk 与质量计算验证新 API 的集成应用。
- 兼容性检查表：现有测试套件的通过情况追踪。
- 验证说明文档与结果记录：沉淀每个优化的验证证据。

## 六、第三方（人 / AI Agent）低成本使用要求

- 第三方应可通过验证说明与结果记录快速定位验证对象与判据。
- 验证脚本应支持快速独立运行，不依赖复杂的前置环境。
- 错误提示应清晰，能快速定位问题原因。

## 七、产出资产关系与后续接口

- 单元测试与算例回放材料共同支撑验证说明文档。
- 兼容性检查表为回归风险评估提供证据。
- 验证总结可作为 Task 收口与后续协作的输入。

## 八、复核要求与 AI 参与边界

- 验证结论应由可复现证据支撑。
- AI 可辅助整理验证记录与生成测试框架，但不替代人工复核。

## 九、待确认项

- 几何接口的维数检查严格程度：是异常抛错，还是自动降维？
- 缓存失效的粒度：是否需要支持部分刷新？
