# FEALPy | Task Object Boundary | 新网格模块算法实现迁移 对象边界

- **版本**：v0.1
- **状态**：草案
- **入库位置**：`kb/developments/new_mesh_module/mesh_05_algorithm_migration/mesh_05_algorithm_migration_task_object_boundary.md`
- **启用条件**：当需要界定当前 Task 的对象边界时，本文件必须启用
- **适用范围**：新网格模块算法实现迁移的直接建设范围与相邻对象分界

本文档用于界定当前 Task 直接建设什么、不直接建设什么，以及与相邻对象如何分界。

## 一、边界定位

本任务专注于 **把算法实现迁移并收敛到 Entity Schema**。迁移对象是算法实现本体，不是接口设计本体，也不是上层调用链路重构。

## 二、纳入范围

本任务**直接建设**以下内容：

- `fealpy/mesh/schema/` 中各实体 Schema 的算法实现迁移与补齐。
- 与算法迁移直接相关的 schema 元数据补充（如方向约定、局部索引规则）。
- 为每种 schema 补齐 `ccw` 类属性（子实体逆时针顺序）。
- 算法迁移映射表、迁移记录与最小验证材料。
- 与迁移算法直接相关的文档说明（如行为差异说明、接口一致性说明）。

## 三、排除范围

本任务**不直接建设**以下内容：

- `fealpy/mesh/view/` 的新 API 设计或重构。
- `fealpy/mesh/storage/` 与 `fealpy/mesh/topology/` 的结构性改造。
- 完整的测试体系与覆盖率提升（由 mesh_06 负责）。
- 上层模块的迁移与联动验证（由 mesh_07 负责）。
- 新网格类型或新算法的设计与引入（除迁移必需的小范围修正外）。

## 四、相邻对象分界

- **与 mesh_03_optimize_architecture 的关系**：mesh_03 提供接口标准与架构优化输入，本任务承接其标准并迁移算法，不重新设计接口。
- **与 mesh_06_test_coverage 的关系**：本任务只提供最小验证材料，覆盖率补强与测试体系扩展由 mesh_06 承担。
- **与 mesh_07_integration_validation 的关系**：本任务不直接做上层模块联动验证，只提供可迁移算法基础。
- **与旧网格模块的关系**：只迁移算法实现，不在本任务内维护旧模块兼容层。

## 五、待确认边界点

- 旧实现中存在“混合 view + schema”的算法，是否拆分迁移或暂留待后续处理。
- 对于依赖 storage/topology 扩展的数据结构，是否允许暂时以 TODO 形式占位。
- 迁移时允许做多少“算法修正”，哪些必须进入后续修复任务。
