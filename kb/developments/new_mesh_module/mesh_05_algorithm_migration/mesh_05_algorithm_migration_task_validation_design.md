## 一、Validation 设计定位

本任务验证的主位不是“重跑全部算法”，而是确认算法迁移 **完整、可追溯、接口一致、可复现**。验证设计强调以低成本方式证明迁移结果可用，并能回链到具体 schema 方法。

## 二、待验证对象与对象级完成判据对应关系

| 待验证对象 | 对应完成判据 |
|-----------|--------------|
| 迁移映射表完整性 | 优先级算法已全部迁移且可追溯 |
| Schema 算法实现 | 算法可通过 schema/EntityView 调用且结果一致 |
| 维度语义一致性 | `normal/tangent` 返回形状一致且语义明确 |
| `ccw` 元数据 | 各 schema 的 `ccw` 可查且顺序可解释 |
| 验证资产 | 每类算法至少一种可复现验证方式 |

## 三、Validation 子任务清单

- **V1**：迁移映射表完整性验证
- **V2**：几何类算法正确性验证
- **V3**：`multi_index` 一致性验证
- **V4**：局部索引与规则算法验证
- **V5**：二维/三维法向与切向语义验证
- **V6**：`ccw` 元数据验证
- **V7**：迁移差异与风险记录核验

## 四、单子任务主类型、验证路径与 Workflow 模式

### V1. 迁移映射表完整性验证

- **主类型**：结构完整性验证
- **验证路径**：迁移清单 ↔ schema 实现对照
- **验证方法**：人工审查 + 简单脚本检查

### V2. 几何类算法正确性验证

- **主类型**：功能正确性验证
- **验证路径**：二维/三维网格样例计算
- **验证方法**：单元测试或对照脚本

### V3. `multi_index` 一致性验证

- **主类型**：一致性验证
- **验证路径**：旧实现输出 ↔ 新 schema 输出
- **验证方法**：脚本对比或回归测试

### V4. 局部索引与规则算法验证

- **主类型**：结构规则验证
- **验证路径**：local entity 索引一致性检查
- **验证方法**：小规模构造样例 + 断言

### V5. 二维/三维法向与切向语义验证

- **主类型**：语义一致性验证
- **验证路径**：不同维度网格的 normal/tangent 输出
- **关注点**：返回形状为 `[实体数, 方向数, 几何维数]`，方向数允许为 0
- **验证方法**：对照计算 + 文档核验

### V6. `ccw` 元数据验证

- **主类型**：结构与规则一致性验证
- **验证路径**：`ccw` 内容与 schema 子实体顺序对照
- **验证方法**：代码审查 + 小规模样例检查

### V7. 迁移差异与风险记录核验

- **主类型**：可追溯性验证
- **验证路径**：差异说明 ↔ 风险记录
- **验证方法**：人工复核

## 五、Validation 子任务产出资产设计

- 迁移对照记录（V1、V7）
- 断言型单元测试（V2、V3、V4）
- 维度语义说明与对照样例（V5）

## 六、第三方（人 / AI Agent）低成本使用要求

- 任何验证结果必须能回链到具体 schema 方法。
- 验证脚本应可独立运行，不依赖复杂环境。

## 七、产出资产关系与后续接口

- 验证记录与测试脚本共同支撑迁移收口与 mesh_06 的覆盖率补强。
- 风险记录进入 mesh_07 的系统查漏输入。

## 八、复核要求与 AI 参与边界

- AI 可辅助生成迁移对照表与初始验证脚本，但关键结论须人工复核。

## 九、待确认项

- 旧实现对照数据的选取范围（最小可复现样例数量）。
- normal/tangent 的维度语义是否需要在验证中强制一致。
