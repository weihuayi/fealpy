# FEALPy | Task Brief | 新网格模块算法实现迁移

- **版本**：v0.1
- **状态**：草案

- **适用范围**：`fealpy/mesh` 新网格模块算法迁移协作、Entity Schema 层算法建设与迁移治理

本文档用于定义当前 Task 的稳定本体表达，回答该 Task 是什么、为什么成立、总体要解决什么问题，以及对象级完成判据为何。

## 一、Task 定位

本任务用于把旧网格模块与新网格模块之间的算法实现迁移到 **Entity Schema** 层，形成“规则模板层可直接承载算法”的稳定结构，使后续 Mesh / EntityView 能以统一的 schema 接口调用算法，而不需要分散到 view 或其他层。

本任务强调 **只向 Entity Schema 迁移算法**，不扩展到 storage、topology、view 等层的改造，也不把算法迁移混写成接口设计任务。

## 二、核心问题与主目标

核心问题是：目前算法实现分散在旧模块或 view 层中，导致新架构下算法调用路径不一致、可维护性差、难以被统一测试与复用。

主目标是：

1. 将核心网格算法迁移并收敛到 `fealpy/mesh/schema/` 的 Entity Schema 中。
2. 统一算法入口与签名，确保迁移后的接口与 mesh_03 的接口标准一致。
3. 补齐各 schema 的 `ccw` 元数据与多重指标 `multi_index` 的迁移基础。
4. 为后续测试覆盖与上层模块验证提供稳定、可复用的算法基础。

## 三、输入与输出预期

**输入预期：**

- mesh_03 阶段形成的接口标准与 schema 设计资产（尤其是 Entity Schema 接口标准）。
- 旧网格模块与现有新模块中已有算法实现的清单与优先级。
- 当前 `fealpy/mesh/schema/` 的代码与能力声明。

**输出预期：**

- 核心算法迁移后的 Entity Schema 实现（按实体类型与算法类别归档）。
- 迁移映射表（旧实现 → 新 schema 方法）与迁移风险记录。
- 最小验证脚本或单元测试，证明迁移算法可用且符合接口标准。
- 迁移完成清单与待回流问题列表。

## 四、对象级完成判据

当且仅当以下条件同时满足，本任务视为完成：

- 迁移清单中优先级最高的算法已全部落到 Entity Schema，且接口签名一致。
- 迁移后的算法可通过 EntityView 或 schema 直接调用，行为与旧实现一致或有明确差异说明。
- 每个迁移算法至少有一种可复现验证方式（单测或验证脚本）。
- 每种 schema 已补齐 `ccw` 类属性并可被查阅。
- `normal()` 与 `tangent()` 的返回形状满足统一约定。
- 迁移映射表与风险记录齐全，未迁移部分有明确原因与后续入口。
- 未把算法迁移任务扩展为 view、storage 或 topology 层的改造。

## 五、待确认点

- 迁移优先级清单（哪些算法必须在本阶段完成）。
- 2D / 3D 场景下 `normal()` 与 `tangent()` 的统一返回语义。
- 允许迁移时做哪些“兼容性修正”，哪些应留给后续修复任务。
