# FEALPy | Task Execution Workflow | 新网格 Schema 标准接口测试重构

- **版本**：v0.1
- **状态**：草案
- **入库位置**：`kb/developments/mesh_schema_interface_test_refactor/mesh_schema_interface_test_refactor_task_execution_workflow.md`
- **启用条件**：当本任务需要组织盘点、设计、迁移、对照、回归和收口执行时，本文件必须启用
- **适用范围**：新网格 Schema 标准接口测试重构执行

## 一、执行原则

采用“规范盘点 -> 接口盘点 -> case 设计 -> 单一入口迁移 -> 对照验证 -> 删除重复 -> 回归收口”的顺序。任何旧测试只有在有效断言完成迁移并有真实 pytest 证据后才可删除。测试数据必须先依据 `kb/design/mesh/mesh_module_contract.md` 确定顶点顺序、局部面顺序和接口期望，再检查代码是否符合；不得从代码现状生成期望值。

## 二、Workflow Node

| 节点   | 名称        | 输入                                              | 输出                                 | 完成条件                      |
| ---- | --------- | ----------------------------------------------- | ---------------------------------- | ------------------------- |
| N-01 | 规范盘点      | `kb/design/mesh/mesh_module_contract.md` 及其引用文档 | 顶点顺序、局部面顺序、OFace/SFace 和接口契约清单     | 每个测试数据字段都有规范依据            |
| N-02 | 现状与测试盘点   | EntitySchema 接口、现有按形状测试                         | 接口清单、旧测试清单、重复项、规范偏差项               | 每个旧测试函数都有归类，代码偏差不被当作契约    |
| N-03 | 契约冻结      | N-01 规范清单、标准接口文档                                | 输出形状、能力矩阵、断言规则                     | 未决契约已标记，不以代码猜测实现          |
| N-04 | 测试数据设计    | N-01/N-03、各形状和几何场景                              | `tests/mesh/data/schema_cases/` 初版 | 规则/非规则/嵌入/多实体/子集 case 可构造 |
| N-05 | 单一入口迁移    | N-02/N-03/N-04                                  | `test_schema_interfaces.py`        | 接口分组和参数化覆盖已运行             |
| N-06 | 独立参考与交叉检查 | 新入口、规范、解析结果、参考公式                                | 覆盖矩阵、迁移记录、失败清单                     | 非仿射和排序问题有独立证据             |
| N-07 | 旧测试处置     | N-06 结果                                         | 删除、保留或转移清单                         | 每个旧文件有明确处置理由              |
| N-08 | 回归和维护演练   | 新入口、相关 Mesh 测试                                  | pytest 结果、维护演练记录                   | 全部收口证据齐全                  |

## 三、并行与责任

- N-01 必须先完成；N-02 可随后并行盘点，但不得修改 N-01 的规范基线。
- N-03 由规范负责人统一冻结；代码与规范冲突时记录为偏差。
- N-04 由测试数据负责人主导；各形状负责人按几何族模块提供符合规范的 case 和解析期望，避免所有人修改一个数据文件。
- N-05 由统一测试入口负责人维护，避免多人同时改同一测试函数结构。
- N-06 由独立复核人检查参考计算、规范依据和迁移完整性。
- N-07 必须在 N-06 完成后执行。

N-04 的数据模块可以由不同负责人并行维护：simplex、tensor-product、mixed 和 references 分开修改；`schema_cases/__init__.py` 的汇总导出由一名负责人集中维护。N-05 只依赖包导出的统一 `ALL_CASES` 或能力筛选结果，不直接依赖各几何族模块的内部名称。

## 四、验证命令层次

1. 单一接口文件：

```bash
pytest -q tests/mesh/unit/test_schema_interfaces.py
```

2. 相关 Mesh 回归：

```bash
pytest -q tests/mesh/unit tests/mesher/unit
```

3. 全仓库测试：使用项目约定的 `pytest` 入口，并记录既有失败与环境条件。

## 五、反馈回流

- 生产实现缺陷：保留失败 case，回流至对应 Schema 实现任务；
- 测试契约不明确：回流至 N-02，暂停删除旧断言；
- case 数据模型不足：回流至 N-04，不复制接口测试函数，并优先在对应几何族数据模块中扩展；
- 迁移遗漏：回流至 N-04/N-05；
- 非 Schema 测试误纳入：回流至对象边界资产，转移到 topology、mesher、view 或 IO 测试。

## 六、收口条件

- 覆盖矩阵和迁移记录可回算；
- 唯一 Schema 接口测试文件通过定向测试；
- 相关回归测试结果已记录；
- 旧测试的删除/保留决定有依据；
- 维护者完成至少一次新增 case 演练；
- 未决契约、既有失败和未覆盖范围没有被隐藏。
