- **适用范围**：Schema 标准接口测试重构的 Verification、Validation 和结果回流设计

## 一、V&V 定位

V&V 的规范基线是 [`kb/design/mesh/mesh_module_contract.md`](../../design/mesh/mesh_module_contract.md)。验证应判断实现和测试是否符合该约定，而不是判断测试是否复现当前代码；当二者冲突时，失败是有效证据。

本任务同时需要：

- **Verification**：确认测试代码、case、断言和迁移结果符合已定义的接口与重构需求；
- **Validation**：确认维护者能够通过新增 case 和标准接口测试扩展形状，而无需复制整套按形状测试文件。

V&V 结果支持任务收口和后续测试维护，不替代生产代码 Bug 裁决或新网格模块最终验收。

## 二、Verification 设计

| V-编号 | 对象            | 验证目标                                 | 主要证据                                    |
| ---- | ------------- | ------------------------------------ | --------------------------------------- |
| V-01 | 测试数据包        | 各几何族模块中的 case 和能力声明依据规范可构造且可重复       | 规范引用、case 构造结果、context 形状、pytest 输出     |
| V-02 | 标准接口测试        | 接口分组、参数化、输出值/形状/有限性断言完整              | `test_schema_interfaces.py`、覆盖矩阵、pytest |
| V-03 | 独立参考计算        | 非仿射积分参考值不复用生产积分逻辑                    | 参考公式、对照结果、代码审查                          |
| V-04 | 迁移完整性         | 旧测试有效断言已迁移或有明确处置                     | 迁移记录、旧新测试对照、差异审查                        |
| V-05 | 约定回归          | 规范定义的 Quad 环状顺序、Hex 顶点顺序和局部面顺序可被测试捕获 | 规范引用、节点映射、局部面循环、法向/体积断言                 |
| V-06 | backend/index | 支持的 backend 和 `index` 子集行为符合矩阵       | 参数化 pytest 输出                           |

## 三、Validation 设计

| C-编号 | 真实使用问题            | 确认方式                          | 使用边界              |
| ---- | ----------------- | ----------------------------- | ----------------- |
| C-01 | 新增一个形状是否只需增加对应数据模块中的 case | 添加试验 case 并运行唯一测试文件 | 只确认 Schema 标准接口范围 |
| C-02 | 失败是否能定位到接口和数据     | 人工检查失败 node id、case id 和参数化报告 | 不评价 pytest 外部报告平台 |
| C-03 | 测试数据是否可复用         | 由非原作者依据文档增加一个规则/非规则 case      | 不替代团队培训或长期维护承诺    |
| C-04 | 重构是否降低重复          | 对照迁移前后测试文件、重复 helper 和覆盖矩阵    | 不以代码行数单独判定质量      |

## 四、结果与回流

- 测试实现错误回流到本任务对应文件；
- 生产接口错误保留最小失败用例，回流到 Schema 实现任务；
- 未覆盖接口或形状缺口进入覆盖矩阵和后续测试任务；
- 维护性验证失败时，优先调整 case 数据模型和测试分组设计，而不是复制形状文件。

## 五、收口证据要求

必须同时提供：

1. 覆盖矩阵；
2. 迁移对照记录；
3. 唯一测试文件的定向 pytest 结果；
4. 相关 Mesh/topology/mesher 回归结果；
5. 至少一个新增 case 的独立维护演练记录；
6. 未覆盖和既有失败清单。
