# FEALPy | Task Requirement | 新网格 Schema 标准接口测试重构

- **版本**：v0.1
- **状态**：草案
- **入库位置**：`kb/developments/mesh_schema_interface_test_refactor/mesh_schema_interface_test_refactor_task_requirement.md`
- **启用条件**：当需要将新网格 Schema 测试从按形状组织重构为按标准接口和算法组织时，本文件必须启用
- **适用范围**：FEALPy 新网格模块的 Schema 标准接口测试资产、测试数据和迁移规范

本文档用于界定本任务承接的需求、需要解决的问题、约束条件、成功条件和待核验事项。

## 一、依据优先级

测试数据和标准接口期望值必须以 [`kb/design/mesh/mesh_module_contract.md`](../../design/mesh/mesh_module_contract.md) 及其引用的实体函数约定为规范来源，尤其是顶点顺序、局部面顺序、OFace/SFace 语义和接口输出契约。当前 `fealpy/mesh/schema/` 的实现、现有测试和运行结果只能作为待验证对象，不能反向定义测试预期；如果代码现状与约定冲突，应保留失败证据并回流生产实现任务，不能把 bug 固化为 feature。

## 二、背景与核心问题

当前 `tests/mesh/unit/schema/` 主要按三角形、四边形、四面体、六面体等形状分文件组织。随着 Schema 数量和标准接口增加，该组织方式会造成相同算法在多个文件中重复实现，测试数据、断言风格和接口覆盖不一致，也难以判断所有 Schema 是否遵守同一标准契约。

本任务需要将 Schema 测试重构为：

1. 测试数据集中承载各种形状、维数、嵌入关系、规则/非规则几何和多实体场景；
2. 以 Schema 标准接口和算法类别组织测试；
3. 使用唯一一份 Schema 标准接口测试文件，通过参数化覆盖适用的各种测试数据；
4. 保留拓扑、Mesh view、mesher 和 IO 等非 Schema 标准接口测试的职责边界。

## 三、已确认需求

1. 新测试不得以形状作为主要测试文件划分依据；测试数据包应按几何族拆分，避免所有 case 集中在一个大文件中。
2. 应设置统一的跨形状测试数据包，至少覆盖 segment、triangle、quadrilateral、tetrahedron、hexahedron，以及当前支持的 prism、pyramid、point。
3. 测试数据应包含规则实体、非规则实体、二维/三维嵌入实体、单实体、多实体和 index 子集场景。
4. Schema 标准接口测试应集中到唯一文件 `tests/mesh/unit/test_schema_interfaces.py`；测试数据不要求集中到唯一文件，应放入 `tests/mesh/data/schema_cases/` 包。
5. 测试文件内部按标准接口分组，包括拓扑、几何、映射、Jacobian/梯度、法向/切向、形函数、积分、多重指标和索引一致性。
6. 各测试 case 必须声明其支持的接口；不适用接口必须显式跳过或在参数生成阶段排除，不得散落形状名称判断。
7. 测试断言应同时覆盖输出值、输出形状、有限性、索引行为和跨接口一致性。
8. 非仿射四边形和六面体积分必须使用测试侧独立 Jacobian 测度计算作为参考，不能仅复用生产实现。
9. 六面体顶点排序约定以及四边形 OFace 环状顺序必须在统一测试数据和拓扑/几何接口测试中得到表达。
10. 迁移完成前不得删除旧测试；新旧测试应有覆盖对照，确认新测试已承接旧测试的有效断言后再删除重复文件。

## 四、约束条件

1. 本任务只重构测试组织、测试数据和测试验证逻辑，不借机修改生产 Schema 行为；发现实现缺陷时建立缺陷记录或回流到对应实现任务。
2. 本任务不把 Mesh view、TopologyBuilder、mesher、IO 和兼容 API 的全部测试强行合并到 Schema 接口文件。
3. 不以覆盖率数字替代标准接口覆盖；每项接口必须有适用 case 和明确的完成证据。
4. 测试数据应可重复，不依赖外部文件、全局随机种子或不可控环境状态。
5. 测试应兼容项目支持的 backend；暂不支持的 backend 必须有明确的能力矩阵记录。
6. 测试文件、测试函数和数据名称不得携带任务编号、验证活动名称或具体应用领域名称。
7. 测试数据包必须可作为 Python 包导入，不得依赖从 `unit/` 目录通过文件系统路径手工寻找数据文件。
8. 数据 case 不要求形成“形状 × 接口”的笛卡尔积；应由 case 声明适用接口，由唯一测试入口按能力筛选，避免无意义的数据复制和测试数量膨胀。

## 五、成功条件

本任务完成时应同时满足：

1. 已建立统一测试数据包，能够通过统一 case 接口构造不同 Schema 的 `EntityContext`。
2. 已建立唯一的 `tests/mesh/unit/test_schema_interfaces.py`，按标准接口组织测试。
3. 规则、非规则、嵌入、多实体和子集 case 均被纳入适用的参数化测试。
4. `EntitySchema` 当前公开标准接口均有覆盖矩阵、适用性说明和至少一个有效断言。
5. 新测试覆盖旧按形状测试中的有效行为，不产生无依据的断言删除。
6. 新测试能独立暴露节点排序、Jacobian、法向、测度、映射和 index 契约问题。
7. 定向 pytest 和全量相关测试均有真实执行结果；迁移遗留项、既有失败和未覆盖范围均已记录。

## 六、待核验与待裁决事项

- 当前 `EntitySchema` 各接口的最终标准输出形状是否已全部冻结。
- prism、pyramid、point 的哪些接口应进入统一参数化矩阵，哪些应保留专门拓扑测试。
- 支持的 backend 清单和每个 backend 的最小测试矩阵。
- 旧按形状测试中哪些断言属于历史错误预期，需要先回流生产接口契约确认。
